## Findings, most important first

### 1. The CE 201 lesson URL served a raw source fragment — fixed

`program/lessons/material-balances.html` (an unstyled fragment: no doctype, title, CSS or JS) sat beside the built page at `program/lessons/material-balances/index.html`. Under `cleanUrls` both claim `/program/lessons/material-balances`, and `trailingSlash: false` makes that the canonical URL — every link on the site points at `/program/lessons/material-balances/`, which redirects there. Locally the no-slash URL served the 7,408-byte fragment instead of the 8,686-byte lesson.

This is the one piece of chemical-engineering teaching content on the site, linked from the homepage as "Try the chemical engineering mixer lesson".

Fixed by moving the three source fragments out of the published tree into `source/` folders and adding `source/` (and `tools/`) to `.vercelignore`. Both URL forms now serve the full document.

### 2. The Atomic Arena's script path broke at its canonical URL — fixed

`chemistry/atomic/index.html` loaded `./engine.js`. Served at `/chemistry/atomic`, that resolves to `/chemistry/engine.js`, which does not exist — confirmed 404 locally, while `/chemistry/atomic/engine.js` returns 200. The whole interactive would have failed to load.

### 3. Three pages shipped inline CSS the CSP blocks — fixed

`chemistry/atomic/index.html`, `sources/books/index.html` and `sources/pearson/index.html` each carried an inline `<style>` whose sha256 is absent from `style-src` in `vercel.json`. A local preview applies no CSP, so these looked correct locally and would be stripped in production. For the Atomic Arena that included `[hidden]{display:none!important}`, so content meant to stay hidden would have become visible.

Extracted to `chemistry/atomic/atomic.css`, `sources/books/books.css` and `sources/pearson/pearson.css` and linked with root-absolute paths. `style-src 'self'` already permits these, so no new hash is needed and future edits cannot silently break.

### 4. A misconception repair pointed at a heading that is not on the page — fixed

In the Foundation 2 guided check, choosing the commonest wrong answer ("output 6 is repeated") returned: *Revisit "A function is a relation with a dependable output"*. That heading exists only in Foundation 3. A student acting on the most valuable feedback on the page would search their own page and not find it. Reworded to point at the rule above the widget, keeping the existing deeper link.

### 5. Scrollable tables were not keyboard reachable — fixed

Foundations chapters and the three-model routes wrap wide tables in `overflow-x: auto` containers (measured 440px of content in a 297px box at 375px width) with no `tabindex`. Chrome does not make scroll containers focusable, so a keyboard-only reader could not reach the hidden columns — WCAG 2.1.1. Both generators now emit `role="region"`, `tabindex="0"` and a name taken from the enclosing heading. Verified focusable, in the tab order, and scrollable.

### 6. Twelve prototype pages had two `<h1>` elements — fixed

Each three-route prototype repeated the page title as an `<h1>` in both the sidebar rail and the main column, with identical text. The rail copy is now `<p class="rail-title">`, with `.rail h1` selectors widened and `font-weight:700` restored so the appearance is unchanged (verified: 27px / 700 / same colour on all four families).

### 7. Missing misconception repairs in the CE 201 check — improved

`15`, `17.14` (12 ÷ 70) and `13.33` (the worked example's answer) are plausible wrong answers that fell through to the generic hint. Each now gets a specific repair. `15` is addressed as both "that is the feed concentration" and "that is 12 ÷ 80", since the two mistakes give the same number.

### 8. Silent failure modes in the authoring pipeline — fixed

- A chapter Markdown file not listed in `tools/build-foundation-reading.mjs` was skipped without a word, so a newly written chapter simply never appeared. The build now fails and names the file.
- Neither Markdown renderer supported `-` bullet lists or `###` sub-headings; both were swallowed into a paragraph as literal text. Both are now supported in both generators.
- Foundation 1 loaded `interactions.mjs` although it has no widget. The script is now emitted only for the two routes that do.

## Remaining gaps and recommended next work

### Gap 1 — the build cannot be run end to end on this machine, and half of it is unverified

`tools/build_semester_site.py` and `tools/semester_curriculum.py` generate the 26 semester-1 topic pages. Python is not installed here, so I could neither run nor test that half. I deliberately made **no** changes to it rather than ship unverified edits to a builder I cannot execute. Anyone continuing this work should install Python first and confirm the Python build reproduces the committed pages byte for byte before touching it.

Related: `tools/connect-program.mjs` is string surgery over the Python output. It locates a block with `/<div id="try">[\s\S]*?<\/noscript><\/section><\/div>/` and moves it. Any change to the Python markup breaks it, and it throws rather than corrupting — but it is brittle by construction.

### Gap 2 — the semester-1 topic schema cannot express the stated teaching standard (highest-value next work)

This is the biggest *learning* gap, and it is structural rather than editorial. A topic in `semester-1/curriculum.json` has exactly `idea`, `example`, `context`, `diagnostic`, `transfer`. The limits lesson is therefore one paragraph of explanation, one worked example, and two questions that are **the same problem type** (difference of squares over a linear factor). There is no field for prerequisites, notation, misconceptions, distinct problem types, or figures.

Meanwhile the newer Markdown-driven pipeline (Foundations chapters, the three-model routes) does all of this well. The homepage advertises MA 101, PHY 101 and CHEM 101 as "Course lessons available", and those are the thinnest lessons on the site.

Recommended: extend the topic schema with optional `prerequisites`, `misconceptions`, `problemTypes` and `figure` fields, render them when present, and backfill topic by topic. Optional fields keep the other 25 topics untouched. Do this in the Python builder once it can be run, or move semester-1 onto the Markdown pipeline that already meets the standard.

### Gap 3 — the homepage and the programme map are byte-identical

`index.html` and `program/index.html` are the same 27,405 bytes, written twice by `tools/build-program.mjs`. Two URLs serve one page, and the header's "Programme map" link points at a copy of the page the student is already on. Worth collapsing to one page plus a redirect, or giving the homepage its own shorter entry content.

### Gap 4 — content still missing

Unchanged from the existing docs and still accurate: 289 of the 296 catalogued episodes have no written chapter; 46 of 50 courses are outlines; the only chemical-engineering lesson is the CE 201 starter, which covers steady nonreacting mixing only. Current official course outlines, laboratory procedures and assessment requirements are still needed before any claim of curriculum alignment.
