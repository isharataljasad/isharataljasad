# Whole-programme learning workspace

## Evidence and boundaries

`program/catalog.mjs` is the editable registry. `catalog.json`, the homepage, programme map and course pages are generated by `tools/build-program.mjs`. There are 46 required courses and four elective options. The 2023 plan totals 128 credits; Semester 7 includes two 3-credit elective slots. Do not sum all four options as mandatory credits.

The owner's supplied study-plan image is the placement source for Semesters 2–8. The locally saved college plan adds Semester 1, credit values and elective slots. College descriptions contain code conflicts recorded in the catalog; the map uses plan codes. The college download URLs were unavailable during this update, so the saved copies are reference evidence, not proof that this is the current regulation. No grade, student identifier or original private screenshot is published.

Course outlines are editorial topic groupings, not complete taught courses. Prerequisites are deliberately null until checked against a current official source. Preparation links are learning suggestions. Do not infer enrollment eligibility or student completion from bookmarks, image colours or practice answers.

## Extending the programme

1. Match each new attachment to the course code and document version. Retain its source identity and access conditions internally; do not publish private source documents.
2. Reconcile its weekly scope against the existing course topics. Record code or placement conflicts before changing the registry.
3. Add original lesson content with objectives, prerequisite explanations, conditions, a worked case, appropriate visuals, distinct question families and reasoned answers. A transcript inventory is not a lesson.
4. Add a resource link only after the target exists. `outline-only` stays until content actually exists. A single lesson uses `starter-available`; it does not certify course completion.
5. Check mathematical edge cases, units, local links, keyboard operation, small screens, missing JavaScript and unavailable browser storage. Log which checks were performed.
6. Build, validate and publish. Real student feedback and delayed transfer remain necessary before claiming teaching effectiveness.

Stable course IDs must not depend on semester placement. `resources` holds independent lesson collections; `lessons` holds individually authored lessons. Future courses can use the same record shape. Extend the schema version if new required fields are introduced. Source evidence, available content and learning outcomes are separate properties.

## Where authoring input lives

Anything a builder reads but no student opens goes in a folder named `source/`. `.vercelignore` excludes `source/` and `tools/`, so those files are never deployed. This is not cosmetic: `vercel.json` sets `cleanUrls: true` and `trailingSlash: false`, so `a/b.html` and `a/b/index.html` both claim the URL `/a/b`, and only one of them can win. A source fragment left beside its generated page shadowed the CE 201 lesson this way. `test/routing.mjs` fails the build if that pair ever reappears.

Two consequences follow from the same setting:

- Use **root-absolute** asset paths (`/chemistry/atomic/engine.js`), never `./engine.js`. On a page served at `/chemistry/atomic`, a relative path resolves one level too high.
- Put CSS in a stylesheet, not in an inline `<style>`. `style-src` allows `'self'` plus two fixed hashes; any other inline block is silently dropped in production while it still works in a local preview.

Run `node tools/preview-server.mjs` for a local preview that reproduces both URL rules. It does not run the access gate.

## Build order

For programme or models work:

```
node tools/build-foundation-models.mjs
node tools/build-program.mjs
node tools/connect-program.mjs
node test/program.mjs
```

If rebuilding the older semester or Foundations libraries, run their own builders first, then `connect-foundations.mjs`, and finally the commands above. The semester builder no longer overwrites the programme homepage.

The three Foundation variants remain separately addressable. The final combined engine is still an editorial decision; improving the pilot does not silently merge it.
